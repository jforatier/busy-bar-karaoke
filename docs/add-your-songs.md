# Add your own songs

A BB Karaoke song is a folder with three files: a **backing track** you own, **lyrics** you time yourself, and a small **`song.json`**. This guide shows how to make a backing track that sounds good on the BUSY Bar, using karaoke-version.com.

> **Your songs stay private.** Everything under `songs/` is git-ignored, except the bundled sample. Purchased tracks and published lyrics are protected: don't commit them, push them to a public fork, or share a `.tgz` built with them.

## 1. Get a custom backing track (karaoke-version.com)

[karaoke-version.com](https://www.karaoke-version.com) (in French: [version-karaoke.fr](https://www.version-karaoke.fr)) sells professionally re-recorded covers. On a song's page, choose **Custom Backing Track MP3** (French site: *Playback Personnalisé MP3*). The mixer gives one fader per instrument.

The BUSY Bar's speaker is small: it plays **one mono channel** and has **little bass**. The bar also normalizes loudness, so whatever is loudest in your mix sets the volume of everything else. Mix with that in mind:

| Track (EN / FR) | Setting | Why |
|---|---|---|
| **Lead vocal / Guide vocal** | **0 %**, or 15–25 % for a "learning" version | It's karaoke: you sing. A faint guide helps for songs you don't know. |
| **Click / Décompte** | **off** | A count-in delays the song. If you leave it on, set `offsetMs` in `song.json` to its length in ms. |
| Drums / Batterie | 40–60 % | Kicks are lost on the speaker but still eat headroom, which makes the mix quieter. |
| Bass / Basse (electric or synth) | 30–50 % | Barely audible on the speaker. Same headroom issue. |
| Piano, guitars, synth pads, strings, brass | 100 % | These carry the harmony in the mid range, where the speaker is good. |
| **Melody / theme lines** (e.g. *Cuivres synthétiques (thème)*) | 100 % | They are your best pitch reference without a guide vocal. |
| Backing vocals / Chœurs | 100 % | Fun to sing over, and they sit well on the speaker. |
| Sound effects | to taste | — |

Leave pan (L/C/R) centred: the bar is mono, so panning changes nothing. Then **download the full MP3**. The *excerpt* (e.g. "Extrait à 02:59") is only the preview point on the site.

Before going further, listen to one verse of the downloaded file. If you still hear the lead vocal or the drums at full level, your fader settings were not applied: set them again and download again.

## 2. Create the song folder

```
songs/my-song/
├── Artist_Title(Custom_Backing_Track).mp3   ← as downloaded, no need to rename
├── song.json                                ← you write it (step 2)
├── lyrics.txt                               ← you type it (step 3)
└── lyrics.lrc                               ← generated by npm run sync (step 3)
```

karaoke-version.com gives you the MP3 only: the two small text files are yours to write.

- The folder name is the song's id: lowercase letters, digits and `-` only, 40 chars max.
- The folder holds exactly one audio file (or name it `track.mp3`).
- `song.json`, from the song page:
  ```json
  { "title": "My Song", "artist": "The Artist", "offsetMs": 0, "bpm": 120 }
  ```
  Accents are fine: the bar only displays ASCII, so `é` becomes `e` automatically. `bpm` is optional: copy the page's *Tempo* (with a variable tempo, its approximate value). It drives the beat indicator of the *ticker* lyric style.

## 3. Type and time the lyrics

The lyrics aren't in the MP3 and the site doesn't provide them. Put them in `lyrics.txt`, typed or pasted from a lyrics page you have access to:
- one sung line per line, whatever its length;
- blank lines are ignored, so pasted text works as it is;
- `~` alone on a line marks an instrumental break in the middle of the song (the intro is handled for you). The bar then shows the next line, with a 3-2-1 count-in on the beat if the break is long enough.

```
Au clair de la lune, mon ami Pierrot,
Prête-moi ta plume pour écrire un mot.
~
Ma chandelle est morte, je n'ai plus de feu.
```

Then time it by ear:

```sh
npm run sync my-song
```

The song plays on your computer. Press **Enter** (or Space) when each line starts, including each `~`. **Backspace** undoes the last tap, and **q** stops and saves. Tap a hair early rather than late.

It writes `lyrics.lrc` (an older one is kept as `lyrics.lrc.bak`). Lines too wide for the 72 px screen are split between words into screen-sized parts, each timed in proportion to its characters. One tap per sung line is enough.

`lyrics.lrc` is a plain text file you can fix by hand. Each line starts with its time:

```
[00:04.00]Au clair de la lune,
[00:06.00]mon ami Pierrot,
[00:08.00]Prête-moi ta plume
```

To shift a whole song, use `offsetMs` in `song.json` (negative = earlier).

## 4. Convert and install

```sh
npm run songs     # needs ffmpeg on PATH
npm run build && npm run app:install && npm run app:run
```

`npm run songs` converts the track to the bar's format (44.1 kHz 16-bit mono PCM, loudness-normalized) and checks the lyrics. It warns about characters it couldn't convert and prints the package size. A folder without `lyrics.lrc` yet is skipped, with a warning.

**Size limit:** about 5.3 MB per minute of audio, and one app build holds up to about 100 MB, so roughly 4–5 full songs. Keep a few favourites in `songs/` and swap them out.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Every song's lyrics are early or late by the same amount | Please open an issue on GitHub with your firmware version: the app's clock is calibrated in code. |
| One song is off | `offsetMs` in its `song.json`. If it drifts over time instead, please open an issue on GitHub. |
| Too quiet / muddy | Lower drums and bass in the karaoke-version mixer and download again. |
| `ffmpeg not found` | Install ffmpeg (Windows: `winget install ffmpeg`; macOS: `brew install ffmpeg`; Linux: your package manager). |
| `?` in lyrics | A character with no ASCII equivalent. Rewrite that word in `lyrics.lrc`. |
