# 03 — Songs

From a song folder to `src/sounds/*.snd` + `src/songs.gen.ts`. Bundled songs are synthesized from a score; a user's song brings its own audio (a 4:48 karaoke-version.com track goes end to end: 11 MB MP3 → 25.4 MB `.snd`).

## Song folder

```
songs/
├── au-clair-de-la-lune/      ← bundled public-domain song, committed
│   ├── score.json            ← the arrangement and its lyrics, synthesized at build time
│   └── song.json             ← title, artist
└── my-song/                  ← user songs: the whole folder is git-ignored
    ├── <anything>.mp3        ← the file as downloaded; any format ffmpeg reads
    ├── song.json             ← written by hand from the song page
    ├── lyrics.txt            ← lyrics typed or pasted by the user
    └── lyrics.lrc            ← generated by npm run sync (or hand-written)
```

- A folder with a `score.json` is synthesized ([Scores](#scores)). Otherwise the audio is `track.*` if present, otherwise **the only audio file** in the folder (`scripts/files.mjs`). A `.snd` is copied as is; anything else goes through ffmpeg.
- The folder name is the song id: `[a-z0-9-]`, ≤ 40 chars, so `sounds/<id>.snd` stays within the 64-char audio path limit.
- `song.json`: `{ "title", "artist", "offsetMs", "bpm" }`. `bpm` is optional and sets the count-in's beat (1 s without it). karaoke-version.com prints it on the song page (*Tempo*, "variable (environ 129 BPM)" → 129).
- karaoke-version.com provides **only the MP3**: no lyrics, no LRC, no metadata file.

## Lyrics: from lyrics.txt to lyrics.lrc (`npm run sync <id>`)

- `lyrics.txt`: one **sung line** per line, any length. **Blank lines are ignored**, because lyrics pasted from a web page come with a blank line between every line. A line containing only `~` marks an instrumental break.
- `npm run sync <id>` plays the audio on the PC (`ffplay -nodisp`, which ships with ffmpeg). The user presses Enter at the start of each sung line (one tap per line, not per screen line). Backspace undoes, q saves.
- **Debounce of 300 ms**: a held key auto-repeats every ~130 ms. In the first real test, 22 lines got "tapped" in 3.5 s.
- On save, each line wider than 70 px is **split at spaces into balanced parts** (`scripts/split.mjs`, widths measured with the bar's own font metrics). Each part's time is interpolated by characters between its tap and the next; the last line uses the song's median ms/char. Real song: 40 pasted lines (median 150 px, up to 218 px) → 115 screen lines, all ≤ 70 px.
- `--keep N` resumes a sync: it recovers the first N taps from the current `lyrics.lrc` (the first part of each sung line), restarts the music 3 s before tap N, and continues. Any previous `lyrics.lrc` is kept as `lyrics.lrc.bak`.
- **Lyrics are copyrighted.** The repo and its tools never ship or fetch them: the user types or pastes them into a git-ignored folder. Only public-domain lyrics are committed ([13](13-legal.md)).

## LRC format accepted

```
[00:04.00]Au clair de la lune,
[00:08.00]Mon ami Pierrot,
[00:12.00]
```
- One line = one timestamp; an empty text marks an instrumental gap (it triggers the count-in, see 02).
- Metadata tags `[ti:]`, `[ar:]`, `[offset:]` are accepted. Per LRC convention, a positive `[offset:]` means earlier, so it is subtracted.
- Several timestamps on one line are expanded. Word-level tags `<mm:ss.xx>` are stripped (v1).
- **ASCII transliteration** (the display is ASCII-only): Unicode NFD + remove combining marks, then a small map (`œ→oe æ→ae ß→ss ’‘→' “”→" …→... –—→-`). Any other non-ASCII character becomes `?`, with a warning and the line number.

## Generation (every build, or `npm run songs`)

`scripts/songs.mjs` runs inside `busy-cli build` through a Vite plugin (`vite.config.mjs`): the generated files are git-ignored, and a clean clone still builds with `busy-cli build` alone, as the BUSY Apps Catalog does. `npm run songs` runs it on its own (e.g. before a typecheck). For each `songs/*/`:
1. **No `lyrics.lrc` yet → skipped with a warning**, so a song in progress doesn't block the others.
2. Audio → `src/sounds/<id>.snd`: the score rendered by `scripts/synth.mjs`, or `ffmpeg -ac 1 -af loudnorm=I=-6:TP=-2 -acodec pcm_s16le -f s16le -ar 44100`. This matches the firmware's converter minus its speaker EQ. A 4:48 MP3 converts in ~7 s.
3. `durationMs = size / 88.2`. A warning is printed if the last lyric is after the end of the audio.
4. Parse + transliterate the LRC, and **measure each line's width** (and the title's) with `textWidth` from `@busy-app/busy-lib` + `@busy-app/busy-lib/fonts`. The app then needs no font maps at runtime.
5. Write `src/songs.gen.ts` (git-ignored, imported by `main.ts`): `SONGS: [{ id, title, titleW, artist, durationMs, offsetMs, countMs, lines: [{ t, text, w, k, c, r }] }]`: per line, `w` = its width in `bold`, `k` = `[t0, x0, …, end, w]` (each syllable's start time and the bold width of the text before it, then the end of the last note), `c` = each syllable's first character (a line without a score is one syllable from its time to the next line's), `r` = where the line wraps on the back display (`[i1, x1, …]`, first character and bold x of each row after the first).

Errors stop the build and name the song folder: no audio, invalid id, invalid `song.json`, ffmpeg missing (with an install hint), over the size budget. CI runs the typecheck after the build, which generates the file the app imports.

## Size budget

5.3 MB per minute, and PCM barely compresses (27.4 MB of audio → 27.1 MB `.tgz`). The 104 MB package limit therefore holds about **4–5 four-minute songs**. The script fails above 100 MB. USB install runs at ~165 KB/s: 27 MB takes 165 s.

## Scores

A bundled song is a `score.json` we write from the traditional melody ([13](13-legal.md)), rendered by `scripts/synth.mjs` in pure Node:

```json
{
  "bpm": 120, "meter": 4,
  "intro": ["C", "G"],
  "chords": ["C", "C", "G", "C"],
  "outro": ["C"],
  "pickup": 0,
  "melody": "C5 C5 C5 D5 E5:2 D5:2 C5 E5 D5 D5 C5:4"
}
```
- `meter`: beats per bar (2, 3, 4 or 6). `chords`: one per bar under the melody; `intro` and `outro` bars are chords alone.
- `melody`: note name + octave (`C5`, `F#4`, `Bb4`), optional `:beats` (default 1, fractions allowed), `r` for a rest. `pickup`: beats of melody before the first bar (anacrusis), taken from the last intro bar.
- The melody's length must equal the chords' bars (plus the pickup): the build fails otherwise, naming the song.
- Sound (see [02](02-design.md#sound)): the melody as written on a 25 % square wave (write it in octave 4–5 so it carries on the small speaker); the accompaniment on triangle waves, root on strong beats and the rest of the chord on the others (oom-pah in 2 and 4, oom-pah-pah in 3 and 6), roots kept between G3 and F#4; the last bar holds its chord. Peak normalized to 85 %.
- `lyrics`: `[[beat, "text"], …]`, the beat counted from the first melody note (0 = the pickup, or bar 1 without one); an empty text marks the end or a gap. Inside a text, spaces split words, `|` splits a word into syllables (`Dash|ing`), `_` is a space inside one syllable (an elision: `le_est`), and a lone `~` holds the previous syllable over one more note (`night ~`). Each syllable takes the next note, rests skipped; **a line must use exactly the notes before the next line**, or the build fails with the counts. The build times each syllable on its note: t = (intro bars × meter − pickup + beat) × 60 / bpm. A scored song needs no `lyrics.lrc`.

| Song | Meter, tempo | Form | Length |
|---|---|---|---|
| *Au clair de la lune* | 4/4, 120 | intro 2 bars, verse A A B A, held chord | 38 s |
| *Jingle Bells* | 4/4, 140 | intro 2, verse 1 (16 bars), chorus ×2 (16), outro 1 | 60 s |
| *We Wish You a Merry Christmas* | 3/4, 132, pickup 1 | intro 2, two verses (8 bars each), outro 1 | 26 s |
| *Silent Night* | 6/8 (eighth = 150), in F | intro 2, verse 1 (24 bars), outro 1 | 65 s |
| *Funiculì, Funiculà* | 6/8 (eighth = 300), in F | intro 2, chorus ×2 (16 bars), outro 1 | 42 s |
| *La Cucaracha* | 4/4, 180, pickup 2 | intro 2, chorus ×2 (8 bars), outro 1 | 25 s |
| *Can-Can* | 2/4, 160 | intro 4 (room for the count-in), main theme ×2 (16 bars) on "ta", outro 1 | 28 s |

Total 23.7 MB of audio for seven songs, a 21.2 MB package.

## Scripts and tests

- `npm run songs` = `songs.mjs` (also run by the build). `npm run preview <id>` = `preview.mjs`: a score rendered to `dist/<id>.wav`, to listen while writing it. `npm run sync <id> [-- --keep N]` = `sync.mjs`.
- `npm test` = `node --test scripts/*.test.mjs`. It covers the LRC parser, transliteration, `lrcTime`, line splitting/timing/tap recovery (`split.mjs`), the synth (notes, chords, score layout, rendered length and level), the changelog checker, and the app's timing maths (`src/timing.ts`, imported directly thanks to Node 24 type stripping): 29 tests.
- The interactive part of `sync.mjs` (raw keyboard + ffplay) has no automated test.
